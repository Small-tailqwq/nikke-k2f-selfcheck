# NIKKE K2F 노출 범위 자가 점검 도구

NIKKE Launcher 공급망 사고에서 발견된 K2F 샘플의 수집 목록을 바탕으로, 해당 위치가 이 컴퓨터에 있는지 확인하고 브라우저에 저장된 비밀번호와 쿠키의 암호화 방식을 집계해 로컬 HTML 보고서를 만듭니다.

위치가 있다고 해서 데이터가 읽히거나 유출된 것은 아닙니다. 이 도구는 감염을 탐지하지 않으며, 유출 여부도 확인할 수 없습니다. K2F 실행 흔적은 [Sheisback/nikke_malware_scanner](https://github.com/Sheisback/nikke_malware_scanner)로 확인하세요.

## 다운로드

[Releases](https://github.com/Small-tailqwq/nikke-k2f-selfcheck/releases)에서 `k2f-selfcheck.exe`를 내려받아 더블클릭하세요. 보고서는 exe와 같은 폴더에 저장되며 기본 브라우저로 열립니다.

exe는 이 저장소의 소스로 GitHub Actions에서 빌드합니다(PyInstaller 단일 파일). 함께 게시되는 `.sha256` 파일로 검증할 수 있습니다.

```powershell
Get-FileHash .\k2f-selfcheck.exe -Algorithm SHA256
```

PyInstaller로 만든 실행 파일은 일부 백신 프로그램에서 오진될 수 있습니다. 걱정된다면 소스로 직접 실행하세요.

## 소스로 실행

Windows 10/11과 Python 3.11 이상이 필요하며, 별도로 설치할 패키지는 없습니다.

```powershell
python k2f_selfcheck.py
```

소스로 실행하면 보고서는 기본적으로 스크립트 폴더에 저장됩니다. `--out`의 상대 경로는 실행 시 작업 폴더를 기준으로 하며 절대 경로는 지정된 위치에 저장됩니다.

| 옵션 | 용도 |
|---|---|
| `--lang` | 보고서와 출력 언어: `zh`, `en`, `ja`, `ko`. 기본값은 Windows 표시 언어를 따르며, 그 밖의 언어에서는 영어를 사용합니다 |
| `--out` | 보고서 경로(`.html` 또는 `.htm`). 이미 있는 파일은 덮어쓰지 않습니다 |
| `--no-open` | 보고서만 저장하고 브라우저는 열지 않습니다 |
| `--quick` | Chromium 데이터베이스와 지갑을 건너뛰며 다른 대상은 점검합니다 |
| `--no-browser-count` | 브라우저 데이터베이스를 건너뜁니다 |
| `--targets` | 사용할 대상 목록. 기본값은 스크립트와 같은 폴더의 `k2f_targets.json` |

종료 코드 `0`은 보고서 작성 성공, `2`는 실행 환경, 입력, 쓰기 중 하나의 실패를 뜻합니다. 종료 코드는 감염이나 유출 상태와 관계없습니다.

## 보고서 내용

보고서를 열면 먼저 안내문이 표시되며, '확인했습니다' 버튼은 6초 뒤에 누를 수 있습니다. 본문은 요약, 브라우저 데이터, 자격 증명 위치, 지갑 확장 프로그램, 미완료 점검, 설명 순서입니다.

- **v10: 고위험.** 현재 사용자 권한으로 실행되는 프로그램이면 복호화할 수 있습니다. 사이트마다 비밀번호를 바꾸고, 다른 기기에서 로그아웃하고, 2단계 인증을 켜세요.
- **암호화되지 않은 쿠키: 샘플의 수집 대상 아님.** 샘플은 `encrypted_value`를 조회합니다. `value`에만 있는 기록은 따로 표시하며 이 샘플의 고위험 항목으로 세지 않습니다.
- **알 수 없는 형식:** 보호 방식을 판단할 수 없으므로 v10과 같이 처리하세요.
- **v20: 낮음.** 앱 바인딩 암호화로 보호되어 있어 복호화하려면 관리자 권한이나 브라우저 프로세스 주입이 필요합니다. v10을 처리한 뒤 중요한 사이트에서 로그아웃하세요.
- **자격 증명 위치:** 존재하는 설정 파일, 자격 증명 파일, 키 폴더를 도구별로 보여 주고, 분류마다 교체 방법을 안내합니다. 프로그램 폴더와 일반 사용자 폴더는 따로 모으며 자격 증명 위치로 세지 않습니다.

숫자는 기록 수 또는 대상 템플릿 수이며, 유출된 자격 증명의 수가 아닙니다.

상세 내용에서 비밀번호는 기록마다 사이트, 마스킹된 계정, 브라우저를, 쿠키는 사이트별 개수를 보여 줍니다. 긴 목록은 고정된 행 높이로 나눠 그리며 화면 밖 부분은 브라우저가 건너뛰므로, 수만 건의 기록도 바로 펼칠 수 있습니다. 보고서에는 스크립트가 없으며 외부 리소스도 불러오지 않습니다.

## 점검 범위와 개인 정보

- 일반 대상은 경로와 파일 메타데이터만 점검합니다. 프로젝트 설정, Firefox의 `key4.db` / `logins.json`, GPG 키 파일, `KUBECONFIG`에 지정된 파일, NIKKE 자격 증명 파일도 확인하며 비밀 내용은 읽지 않습니다.
- 프로젝트 검색은 깊이 2까지 진행하고 `.git` / `node_modules` 및 `.example` / `.sample` / `.template` 파일을 제외합니다. SSH 설정과 PuTTY / WinSCP 세션에서는 외부 키 경로와 비밀번호 필드 유무를 확인합니다.
- 프로세스와 사용자/시스템 레지스트리 환경 변수를 샘플 규칙으로 선별하며 보고서에는 변수 이름만 남깁니다. Windows 자격 증명 관리자는 항목 수만 집계합니다. 환경 변수 값, 자격 증명 내용, 실제 사용자 지정 경로는 기록하지 않습니다.
- Chromium 데이터베이스는 공유 읽기 전용으로 메모리에 불러와 암호화 접두사를 확인합니다. 복호화하거나 원본에 쓰지 않습니다. Chrome, Edge, Brave, Vivaldi, Opera의 알려진 루트 아래에 있는 모든 프로필 하위 폴더를 확인하며 Opera 루트 데이터베이스와 루트 밖의 포터블 프로필은 제외합니다. 지갑은 Chrome에서만 점검하며 확장 프로그램 설치 여부와 해당 컨테이너의 `.ldb` / `.sst` / `.log` 파일을 확인합니다.
- 브라우저 상세 정보에는 사이트 호스트 이름, 프로필 번호, 마스킹된 계정만 남깁니다(4자 이하는 모두 숨기고 그 밖에는 첫 글자와 마지막 글자만 표시). URL 경로와 매개변수, 비밀번호, 쿠키 이름과 값, 토큰, 개인 키는 포함하지 않습니다. 사이트 목록과 환경 변수 이름도 개인 정보이므로 보고서를 공개하지 마세요.
- 네트워크 경로, 네트워크 드라이브, 재분석 지점은 제외합니다. 설정되지 않은 환경 변수는 해당 없음으로, 샘플의 4MiB 제한을 넘는 브라우저 파일은 샘플이 건너뛰는 항목으로 표시합니다. 읽기 실패는 미완료로 남깁니다. 병합되지 않은 WAL이 있으면 기본 파일만 집계하고 불완전으로 표시합니다.

대상 경로와 탐지 규칙은 K2F LuaJIT 번들(SHA-256 `cc0ad05bfe85940a6067b3a72c182d3953339129206634141926d5d0b35973ec`)의 정적 분석에서 복원했습니다. 파일 존재 여부는 저장 위치 후보를 나타내며, 설정·기록·세션 내용의 추출이나 복호화는 재현하지 않습니다.
